# 03 · 系统与系统参数

系统是 ECS 的"行为层"。PureEcs 的哲学是：**系统就是一个普通函数，它想读哪些数据，就声明哪些参数**；参数的类型由 `params()` 自动推断，绝大多数情况不需要手写类型标注。

## 系统的三种形态

### 1) 裸函数系统（接收 World）

最直接的形式：一个接收 `World` 的函数。

```ts
import { World } from 'pureecs';

function setup(world: World): void {
  const e = world.spawnWith(new Position(0, 0));
  world.insertResource(new Gravity(9.8));
}
```

它可以被注册为启动系统，也可以作为普通系统：

```ts
new App()
  .addStartupSystem(setup)   // 启动时跑一次
  .addSystem(tick)           // 每个 tick 跑
  .run(60);
```

系统接收的 `world` 可以直接完成 `docs/02` 的全部 CRUD 操作、资源读写、事件读写等。**任何系统最保守的写法就是只拿 `World`**，灵活但丧失声明性。

### 2) `params(...)` 声明式系统（推荐）

用 `params()` 描述"我想要什么"，框架负责在每一帧把数据取好、推断类型，然后调用你的回调：

```ts
import { App, params, Query } from 'pureecs';

class Position {
  constructor(public x = 0, public y = 0) {}
}
class Velocity {
  constructor(public x = 0, public y = 0) {}
}

const movement = params(Query(Position, Velocity)).system((rows) => {
  for (const [pos, vel] of rows) {
    pos.x += vel.x;
    pos.y += vel.y;
  }
});
```

> 关于每个参数会被注入成"数组"还是"单值"，规则是：
> **普通组件类 / `Query()` → 数组（多实体）**；**`Res`/`ResMut`/`Single`/`Cmd`/`Local`/事件读写器 → 单值**。

### 3) `world.addSystem(...)` 注册入口

`params(...).system(...)` 产出的东西本质是一个 `(world: World) => void` 函数（`SystemFn`），注册方式都一样：

```ts
new App()
  .addSystem(movement)                     // 默认 Stages.Update
  .addSystem(Stages.PostUpdate, render)    // 指定阶段
  .run(1);

// World 同理
world.addSystem(movement);
```

## params 参数：一份完整清单

`params()` 接受以下描述符，按出现顺序注入回调参数：

| 描述符 | 注入形态 | 用途 | 详见 |
| --- | --- | --- | --- |
| `Position`（裸组件类） | `Position[]`（独立数组，与其它参数无关联） | 拿"所有拥有 Position 的实体" | 本文 |
| `Query(A, B)` | `[A, B][]`（每个元组来自同一实体） | **同一实体**多组件联结 | docs/04 |
| `Query(A, With(X), Without(Y))` | 同上 | 带过滤的联结查询 | docs/04 |
| `Entity`（作为 fetch） | 注入实体句柄 | 在查询结果里拿到 `Entity` | docs/04 |
| `Single(A)` | `A \| undefined` | 只取第一个匹配实体 | docs/04 |
| `Res(T)` | `T`（单值，可改引用） | 读资源 | docs/07 |
| `ResMut(T)` | `ResourceMut<T>`（`.get()` 标记变更） | 写资源 + 变更追踪 | docs/07 |
| `Cmd()` | `Commands`（延迟命令队列） | spawn/despawn 等延迟变更 | docs/05 |
| `Local(() => v)` | `v`（首帧初始化，跨帧复用） | 系统本地状态 | 本文 |
| `EventWriter(T)` | `EventWriter<T>` | 发事件 | docs/06 |
| `EventReader(T)` | `EventReader<T>` | 收事件 | docs/06 |

### 独立查询 vs 联结查询（最容易踩的坑）

`params(A, B)` 中 `A` 与 `B` 是**两个独立查询**，分别返回各自的数组——**两者之间没有任何"同一个实体"的关联**。下标对齐只在恰好 A/B 集合与顺序完全一致时才成立，不要依赖它。

如果你需要"同时拥有 A 和 B 的实体"，请用 `Query(A, B)`：

```ts
// ✗ 错误示例：分别遍历，两个数组完全独立
params(Position, Velocity).system((positions, velocities) => {
  for (let i = 0; i < positions.length; i++) {
    // positions[i] 与 velocities[i] 大概率不是同一个实体！
  }
});

// ✓ 正确：Query() 联结，保证每行来自同一个实体
params(Query(Position, Velocity)).system((rows) => {
  for (const [pos, vel] of rows) {
    pos.x += vel.x;
  }
});
```

### 多组件联结 + 过滤器

```ts
params(Query(Position, Health, With(Enemy), Without(Poisoned)))
  .system((rows) => {
    // rows: [Position, Health][] —— 只包含同时有 Position+Health+Enemy、且没有 Poisoned 的实体
    for (const [pos, hp] of rows) {
      pos.x += 1;
      hp.current -= 5;
    }
  });
```

### Local：系统本地状态（跨帧缓存）

需要在一个系统里跨帧保存临时状态时（例如统计、计时、缓存），用 `Local`。它只在**首次执行**时调用一次工厂函数，之后每一帧都注入同一个实例：

```ts
import { App, params, Query, Local } from 'pureecs';

class FrameStats {
  frames = 0;
}

const stats = params(
  Query(Position),
  Local(() => new FrameStats()),   // 首帧创建
).system((positions, s) => {
  s.frames++;
  console.log(`frame ${s.frames}: ${positions.length} entities`);
});

new App().addSystem(stats).run(3);
```

> 提示：把多个值合成一个普通对象/类塞进 `Local` 即可"打包"任意本地状态。

### 混用不同类型参数

`system()` 支持任意组合与顺序：

```ts
const sys = params(
  Query(Position, Velocity),   // → [Position, Velocity][]
  Res(GameConfig),             // → GameConfig
  ResMut(Score),               // → ResourceMut<Score>
  Cmd(),                       // → Commands
  Local(() => ({ n: 0 })),     // → { n: number }
).system((rows, config, score, commands, state) => {
  state.n++;
  for (const [pos, vel] of rows) {
    if (config.speedMultiplier) {
      commands.spawn().with(new Particle(pos.x, pos.y)); // 延迟生成
    }
  }
});
```

### system() 回调的三个注意点

1. 缺少 `Res(T)`/`ResMut(T)` 声明的资源时，会抛出形如
   `Required resource is missing: GameConfig` 的错误，提示缺了什么。
2. 数组/元组参数每一帧都是新分配的，`system()` 适合表达力优先的场景。
3. 回调内修改组件直接改字段即可（返回的是真实引用）。想让"修改"被变更追踪记录，需配合 `ResMut`/`getComponentMut`/`Mut`（见 docs/07）。

## 其它两种 builder：`systemWithWorld` / `systemForEach`

`params()` 除了 `.system(fn)`，还有两个变体。

### systemWithWorld：把 World 也拿进来

回调签名：`(world, entityIds, ...args)`。

```ts
const sys = params(Query(Position, Velocity)).systemWithWorld((world, ids, rows) => {
  // world：完整 World（可做任何操作）
  // ids  : number[] —— 与 rows 对齐的实体 ID（来自第一个查询/单实体查询）
  // rows : [Position, Velocity][]
  for (let i = 0; i < ids.length; i++) {
    console.log('entity id', ids[i]);
  }
});
```

### systemForEach：零分配高性能逐实体回调

`.systemForEach(fn)` 是**性能专用路径**：不先物化整表数组/元组，而是逐实体调用回调。回调参数直接是组件实例，且仅支持**一个 `Query()`** 参数。

```ts
const movement = params(Query(Position, Velocity)).systemForEach((pos, vel) => {
  // 每匹配到一个实体就调用一次，不产生中间数组
  pos.x += vel.x;
  pos.y += vel.y;
});
```

约束与取舍：

- `systemForEach()` 只能接受**恰好一个 `Query(...)`**，其它参数（Res/Cmd/Local）都会抛 `TypeError`；
- 回调内禁止**保留**组件引用到回调之外（数据可能被移动）——同步处理即可；
- 查询的 fetch 数量 1~3 时有专用快路径，最常用的联结查询应优先考虑它。

## 何时用哪种系统

| 场景 | 推荐 |
| --- | --- |
| 一次性初始化（生成实体/插资源） | `addStartupSystem(fn)` 裸 World |
| 批量处理某个组件集，性能关键 | `params(Query(...)).systemForEach(...)` |
| 需要多个联结查询/资源/命令组合 | `params(...).system(...)` |
| 回调里要拿 `World` 做底层操作或拿到实体 ID | `systemWithWorld(...)` |

## 可运行示例

```ts
import { App, World, params, Query, Res, Cmd, Local } from 'pureecs';

class Position { constructor(public x = 0, public y = 0) {} }
class Velocity { constructor(public x = 0, public y = 0) {} }
class GameConfig { constructor(public speed = 2) {} }
class TrailPoint { constructor(public x = 0, public y = 0) {} }

// ① 启动系统：裸 World 一次
function setup(world: World) {
  world.insertResource(new GameConfig(3));
  for (let i = 0; i < 3; i++) {
    world.spawnWith(new Position(i * 10, 0), new Velocity(1, 0));
  }
}

// ② 高性能逐实体更新 + 读资源
// 注意：systemForEach 只支持单个 Query()，因此"资源 + 查询"的组合用 system() 更合适：
const move = params(Query(Position, Velocity), Res(GameConfig)).system((rows, cfg) => {
  for (const [pos, vel] of rows) pos.x += vel.x * cfg.speed;
});

// 纯 Query 且想零分配时再用 systemForEach：
const moveFast = params(Query(Position, Velocity)).systemForEach((pos, vel) => {
  pos.x += vel.x;
});

// ③ 延迟命令 + 本地状态
const emitTrail = params(Query(Position), Cmd(), Local(() => ({ tick: 0 })))
  .system((positions, commands, state) => {
    state.tick++;
    if (state.tick % 5 === 0) {
      for (const [pos] of positions) {
        commands.spawn().with(new TrailPoint(pos.x, pos.y));
      }
    }
  });

new App()
  .addStartupSystem(setup)
  .addSystem(move)      // 使用带资源的 move
  .addSystem(emitTrail)
  .run(20);
```

> 若需同时用多个系统，把 `move` 换成 `moveFast`（省去资源读取、演示 systemForEach 零分配版本）即可。

## 小结

- 系统是纯函数，声明参数即可取数，`params()` 自动完成类型推导；
- 裸 `ComponentClass` = 独立查询；`Query(...)` = 同实体联结；`Single` = 取首个；资源/命令/Local/事件读写器 = 注入单值；
- 三种 builder：`.system()`（通用）、`.systemWithWorld()`（加 World + 实体 ID）、`.systemForEach()`（单查询零分配快路径）；
- 资源缺失会以"类型名"明确报错。
