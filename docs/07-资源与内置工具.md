# 07 · 资源与内置工具（Resource / Time / Timer / 变更追踪）

组件是"贴在实体上的数据"，资源（Resource）则是**全局唯一的共享数据**——例如游戏配置、总分、当前关卡、输入状态、全局时钟。资源不属于任何实体，以 **class 作为唯一标识**，同一类型最多存在一份。

本篇同时覆盖变更追踪工具 `Mut` / `ResourceMut`，以及内置资源 `Time`、`Timer`。

## 一、Resource：全局单例数据

### 定义与插入

资源同样是普通 class：

```ts
class GameConfig {
  constructor(public title = 'MyGame', public fps = 60) {}
}
class Score {
  constructor(public value = 0) {}
}
```

通过 App / World / Commands 三种途径插入：

```ts
import { App, World } from 'pureecs';

// ① App 装配期（最常见）
new App().insertResource(new GameConfig('PureEcs Demo', 60));

// ② 启动系统里
function setup(world: World) {
  world.insertResource(new Score(0));     // 按实例 constructor 自动识别类型
  world.insertResourceAs(Score, new Score()); // 显式指定类型
}

// ③ 延迟（Commands，见 docs/05）
commands.insertResource(new GameConfig('x', 30));
```

要点：

- `insertResource` 使用 `resource.constructor` 作为类型标识，因此**必须传 class 实例**；
- 相同类型再次插入会**整体覆盖**旧实例；
- 类型与值可分离（用于基类/工厂场景）时用 `insertResourceAs(Type, value)`。

### 读取 / 写入 / 删除

World 直接 API：

```ts
const cfg = world.getResource(GameConfig);         // GameConfig | undefined
if (cfg) console.log(cfg.title);

const required = world.getRequiredResource(GameConfig); // 没有则抛错（明确报“缺什么”）
world.removeResource(Score);                        // 返回被删实例 | undefined
world.hasResource(GameConfig);                      // boolean
```

系统参数 API（推荐）：

```ts
import { params, Query, Res, ResMut } from 'pureecs';

class Velocity { constructor(public x = 0) {} }

// 读：Res(T) —— 注入的就是资源实例
const applyConfig = params(Query(Velocity), Res(GameConfig)).system((rows, cfg) => {
  for (const [vel] of rows) {
    vel.x *= cfg.fps > 0 ? 1 : 0;
  }
});

// 写 + 变更追踪：ResMut(T) —— 注入 ResourceMut<T>，需要 .get() 取到内部值
const addScore = params(ResMut(Score)).system((score) => {
  score.get().value += 100;   // 每次 get() 会标记“本 tick 已修改”
});
```

| 参数 | 注入 | 说明 |
| --- | --- | --- |
| `Res(T)` | `T` | 只读，直接使用 |
| `ResMut(T)` | `ResourceMut<T>` | 通过 `.get()` 取内部值写（标记变更），`.peek()` 读（不标记） |

> 若资源缺失：`Res`/`ResMut` 会抛 `Required resource is missing: GameConfig`。

## 二、变更追踪：Mut / ResourceMut 与 Added / Changed

PureEcs 内置了**本 tick 变更追踪**，支撑查询过滤 `Added(X)` / `Changed(X)`（见 docs/04）。核心规则只有一条：

> **只有通过 `Mut`（或 `ResourceMut`）的 `.get()` 访问，修改才会被标记。**

```ts
import { Mut, ResourceMut } from 'pureecs';

// 组件：World.getComponentMut 返回 Mut<T>
const mut = world.getComponentMut(entity, Position); // Mut<Position> | undefined
if (mut) {
  const pos = mut.get();   // 标记 changed → 本 tick Changed(Position) 命中
  pos.x += 1;
  // const p2 = mut.peek(); // 读取但不标记
}

// 资源：World.getResourceMut / ResMut 参数
const rmut = world.getResourceMut(Score); // ResourceMut<Score> | undefined
if (rmut) rmut.get().value += 10;
```

### 时间窗口与清理

- `Added`：`insertComponent` / `spawnWith` / `Commands.insert` 插入组件时自动标记；
- `Changed`：仅在 `Mut.get()` / `ResourceMut.get()` 时标记；**直接拿普通引用改字段不会被记录**；
- 所有追踪数据在**每次 `update()`（tick）结束时调用 `ChangeTrackers.clear()` 清空**；
- 因此 `Added` / `Changed` 只在"发生的那一个 tick"内可观测，与事件类似。

### 典型用法：只在新增/变化时做事

```ts
// 敌人刚出生时播一声
params(Query(With(Enemy), Added(Enemy))).system(() => {
  playSpawnSound();
});

// 玩家血量被改动后更新 UI
params(Query(Health, Changed(Health))).system((rows) => {
  for (const [hp] of rows) refreshHpBar(hp);
});

// 资源被改动时触发一次性逻辑
params(ResMut(Score), Local(() => ({ last: 0 }))).system((score, state) => {
  const cur = score.get().value;
  if (cur !== state.last) {
    console.log('score changed →', cur);
    state.last = cur;
  }
});
```

## 三、Time：全局时间资源

`Time` 提供帧间隔 `delta` 与累计时间 `elapsed`，并支持**时间倍速**与**暂停**。

### 初始化与驱动

```ts
import { App, Time } from 'pureecs';

const time = new Time();
const app = new App().insertResource(time); // 以资源形式插入，供系统 Res(Time) 读取

// 游戏主循环（伪代码）：
function frame(realDeltaMs: number) {
  time.update(realDeltaMs / 1000); // 传入“秒”为单位的真实 delta
  app.update();
  requestAnimationFrame(frame);
}
```

> 若用了输入插件的 `createTimeSystem`（见 docs/09、docs/10），它会自动在每 tick 开头基于真实耗时调用 `time.update(...)`，无需手动驱动。

### 系统内读取

```ts
import { params, Query, Res } from 'pureecs';

class Position { constructor(public x = 0) {} }
class Velocity { constructor(public x = 1) {} }

// 基于 delta 的帧率无关运动（推荐）
const move = params(Query(Position, Velocity), Res(Time)).system((rows, time) => {
  for (const [pos, vel] of rows) {
    pos.x += vel.x * time.delta;
  }
});
```

### API 摘要

```ts
time.update(realDelta);   // 每帧调用：delta = realDelta * relativeSpeed
time.delta;               // 本帧有效 delta（秒）
time.elapsed;             // 累计有效时长（秒）
time.relativeSpeed;       // 时间倍速（默认 1）
time.relativeSpeed = 0.5; // 半速 / = 0 暂停 / = 2 二倍速
time.pause();  time.unpause();  time.paused();
```

注意：

- `delta` = 传入 delta × `relativeSpeed`；暂停时 `update()` 使 `delta` 归 0 且 `elapsed` 不前进；
- `elapsed` 累计的是**有效时长**，倍速/暂停都会体现；
- 想让"游戏逻辑暂停但 UI 不暂停"，可对 UI 系统传 `Res<Time>` 而 UI 自己记录真实帧时间，或使用倍速只对逻辑系统应用。

## 四、Timer：一次性 / 循环计时器

`Timer` 通常作为资源（全局计时）或组件（挂在实体上）配合 `tick()` 使用。

### 两种模式

```ts
import { Timer, TimerMode } from 'pureecs';

// 一次性：到时后保持 finished，需要 reset() 才能重新开始
const cooldown = new Timer(2.0, TimerMode.Once);

// 循环：到时自动回绕（elapsed %= duration），持续触发
const spawnTimer = new Timer(0.5, TimerMode.Repeating);
```

### 基本用法

```ts
const timer = new Timer(1.0, TimerMode.Repeating);
timer.tick(0.3);
console.log(timer.fraction());     // 0.3
timer.tick(0.8);                   // 累计 1.1 ≥ 1.0 → justFinished=true，回绕到 0.1
console.log(timer.justFinished()); // true —— 只在越过的那一帧为 true

// 系统里驱动一个全局生成计时器：
class WaveTimer {} // 仅作为资源类型占位
```

常用 API 一览：

```ts
new Timer(duration, mode?)   // mode 默认 Once；duration 必须 > 0
timer.tick(delta)            // 推进（负数/非有限值抛 RangeError）
timer.finished()             // 是否已达到 duration
timer.justFinished()         // 是否“刚刚这一 tick”完成（最常用，配合 Repeating 触发事件）
timer.reset()                // 归零（Once 模式重新启用前需要）
timer.fraction()             // [0,1] 完成比例
timer.remaining() / .remainingTime    // 剩余秒数
timer.elapsedSecs() / .elapsedTime    // 已走秒数
timer.fractionRemaining()    // [0,1] 剩余比例
timer.pause() / unpause() / paused()  // 暂停控制（暂停时 tick 不推进）
```

### 完整模式：把计时器当组件挂在实体上

```ts
import { App, World, params, Query, ResMut, Cmd, Entity } from 'pureecs';

class Position { constructor(public x = 0, public y = 0) {} }
class Lifetime { constructor(public remaining = 2.0) {} } // 2 秒后销毁（用 Timer）

function setup(world: World) {
  for (let i = 0; i < 3; i++) {
    world.spawnWith(
      new Position(i * 10, 0),
      new Timer(1 + i * 0.5, TimerMode.Once), // 复用 Timer 作为“寿命”
    );
  }
}

// 每帧推进所有 Timer 组件，Once 到期的实体销毁
const expire = params(Query(Timer, Entity, Cmd())).system((rows, commands) => {
  for (const [timer, entity] of rows) {
    timer.tick(0.1); // delta 应取自 Res(Time).delta，这里用固定值演示
    if (timer.finished()) {
      commands.despawn(entity);
    }
  }
});

new App()
  .addStartupSystem(setup)
  .addSystem(expire)
  .run(30);
```

> 实践中把 `0.1` 替换成 `Res(Time)` 的 `time.delta`，即得到帧率无关的寿命逻辑。

## 资源与组件的选型

| 需求 | 用 |
| --- | --- |
| 全局唯一、跨系统共享 | **Resource** |
| 附着在实体上的持久数据 | **Component** |
| 每帧推进的全局时钟 | `Time` 资源 |
| 一次性 / 循环延迟 | `Timer`（资源或组件均可） |
| 帧内一次性信号 | **Event**（docs/06） |
| 想知道"谁刚新增/改动" | `Added`/`Changed` 过滤器 + `Mut` |

## 小结

- 资源 = 以 class 为键的全局单例；插入 `insertResource`（自动识别）或 `insertResourceAs`（显式）；
- 系统读用 `Res(T)`，写用 `ResMut(T)`（`.get()` 标记变更）；缺失资源明确抛错；
- 变更追踪靠 `Mut`/`ResourceMut` 的 `.get()` 触发，tick 末清空，只在一个 tick 内可观测；
- `Time` 提供 `delta`/`elapsed`/倍速/暂停，是帧率无关运动的基石；
- `Timer` 支持 Once/Repeating 两种模式，`justFinished()` 是触发逻辑的常规入口。
