# 05 · 命令与延迟变更（Commands）

在系统执行过程中直接修改世界结构（生成/销毁实体、插入/移除组件）有一个问题：**同一时刻可能有多个系统在遍历实体**。如果系统 A 正在遍历 `Position` 存储，系统 B 却突然 despawn 实体、改变存储布局，遍历会出错或产生不可预期的结果。

PureEcs 的解法与 Bevy 一致：**命令（Commands）**。所有结构性变更先进入队列，等到**系统执行完毕、进入下一个阶段之前**统一应用到世界。

## 为什么需要延迟

- **一致性**：系统运行期间，世界状态稳定不变，所有查询结果可信；
- **避免遍历失效**：遍历中途增删组件不会导致数组下标错位；
- **顺序可控**：提交与生效分离，多系统间的"先后"不会造成歧义。

```
系统 A ──┐
系统 B ──┼─ 执行期间：只能读稳定世界 / 向 Commands 提交命令
系统 C ──┘
        │
        ▼  Commands.apply()（Stage 结束后统一执行）
   世界被真正修改
```

## 获取 Commands

通过 `params()` 的 `Cmd()` 参数描述符注入：

```ts
import { App, World, params, Query, Cmd } from 'pureecs';

class Position { constructor(public x = 0, public y = 0) {} }
class Bullet    { constructor(public x = 0, public y = 0) {} }

const shoot = params(Query(Position, Cmd())).system((positions, commands) => {
  // 只读查询 + 提交命令
});
```

> 每次系统运行注入的 `Commands` 是同一个 tick 内共享的队列，全部系统都向它追加命令。

## Commands API 一览

```ts
interface Commands {
  spawn(): SpawnBuilder;                                  // 生成实体（可链式挂组件）
  despawn(entity: Entity): void;                          // 销毁实体
  insert(entity: Entity, component: unknown): void;       // 给既有实体插组件
  remove(entity: Entity, componentType: ComponentClass): void; // 移除组件
  insertResource(resource: unknown): void;                // 插入资源
  removeResource(type: ComponentClass): void;             // 移除资源
  apply(world: World): void;                              // @internal 调度器调用
}
```

### 生成实体：spawn + SpawnBuilder

```ts
class Position { constructor(public x = 0, public y = 0) {} }
class Velocity { constructor(public x = 0, public y = 0) {} }
class Lifetime { constructor(public remaining = 60) {} }

const spawnEnemies = params(Query(Position), Cmd()).system((enemies, commands) => {
  for (const [pos] of enemies) {
    commands
      .spawn()
      .with(new Position(pos.x, pos.y))
      .with(new Velocity(0, 1))
      .with(new Lifetime(60));
  }
});
```

`SpawnBuilder` 提供两个方法：

- `.with(component)` —— 追加一个组件，可连续调用；
- `.onSpawn(callback)` —— 命令真正应用后，回调会收到**新实体的 Entity 句柄**。

```ts
// 需要在生成后立刻拿到实体句柄（例如把新实体记录下来）：
let lastSpawned: Entity | null = null;

const spawnWithCallback = params(Cmd()).system((commands) => {
  commands
    .spawn()
    .with(new Position(0, 0))
    .onSpawn((entity) => {
      lastSpawned = entity; // 此时实体已真实存在
      console.log('spawned', entity.toString());
    });
});
```

> `onSpawn` 的回调在 `Commands.apply()` 阶段执行，那时世界已处于稳定可写状态。注意：**不要**在系统执行期读 `lastSpawned` 期待立即可用——命令尚未应用。想要"本 tick 就拿到句柄"，请直接在系统里用 `world.spawn()`（无需延迟）。

### 销毁 / 插组件 / 删组件

```ts
const cleanup = params(Query(Lifetime, Cmd()), Cmd()).system((lifetimes, commands) => {
  for (const [lifetime] of lifetimes) {
    if (lifetime.remaining <= 0) {
      // 这里想拿到对应 Entity？用 systemWithWorld 或查询里 fetch Entity：
      // 见下方说明
    }
  }
});
```

需要拿到实体句柄才能 `despawn`，所以销毁实体通常配合 **`systemWithWorld`**（拿 ID 列表）或查询里 fetch `Entity`：

```ts
import { Entity } from 'pureecs';

// 方式一：查询里带 Entity，直接拿到句柄
const despawnDead = params(Query(Lifetime, Entity, Cmd())).system((rows, commands) => {
  for (const [lifetime, entity] of rows) {
    if (lifetime.remaining <= 0) commands.despawn(entity);
  }
});

// 方式二：systemWithWorld + 命令
const despawnDead2 = params(Query(Lifetime)).systemWithWorld((world, ids, lifetimes) => {
  for (let i = 0; i < ids.length; i++) {
    const entity = world.getEntityById(ids[i])!;
    world.commands.despawn(entity);
  }
});
```

对既有实体插入/移除组件：

```ts
const tag = params(Query(Position, Entity, Cmd())).system((rows, commands) => {
  for (const [pos, entity] of rows) {
    if (pos.x > 100) {
      commands.insert(entity, new OutOfBounds(true));   // 插组件
      commands.remove(entity, Position);                // 删组件
    }
  }
});
class OutOfBounds {
  constructor(public flag = false) {}
}
```

### 资源命令

```ts
class GameState { constructor(public paused = false) {} }

const toggle = params(Query(PlayerTag), Cmd()).system((_, commands) => {
  // ...
  commands.insertResource(new GameState(true));   // 延迟插入（覆盖同名）
  commands.removeResource(GameState);             // 延迟移除
});
```

## 何时应用：Stage 边界 + tick 末尾

严格顺序如下（详见 docs/08 调度）：

1. 系统按顺序执行；
2. 每执行完一个 **Stage**，调度器调用 `Commands.apply(world)`，清空队列；
3. 所有 Stage 结束后进入下一个 tick。

因此：

```ts
// 同一 Stage 内的系统共享同一个"未应用"队列。
// 不同 Stage 之间，前一个 Stage 提交的命令已经被应用，后一个 Stage 能立刻看到新实体。
```

## 使用建议

| 场景 | 推荐 |
| --- | --- |
| 系统执行期间生成大量实体 | `commands.spawn().with(...)` |
| 需要马上知道新实体句柄做后续本 tick 处理 | 直接用 `world.spawn()` |
| 只读查询 + 少量结构变更 | `params(Query(...), Cmd())` |
| 遍历过程中按条件销毁 | 查询带 `Entity`，配合 `commands.despawn` |
| 初始化/启动阶段批量铺场景 | `addStartupSystem` 里直接 `world.spawnWith(...)`（无并发问题，无需延迟） |

## 可运行示例

```ts
import { App, World, params, Query, Cmd, Entity } from 'pureecs';

class Position { constructor(public x = 0, public y = 0) {} }
class Velocity { constructor(public x = 0, public y = 0) {} }
class Lifetime { constructor(public remaining = 3) {} } // 帧数

function setup(world: World) {
  // 3 个会移动的小球，寿命 3 tick
  world.spawnWith(new Position(0, 0), new Velocity(1, 0), new Lifetime(3));
  world.spawnWith(new Position(10, 0), new Velocity(-1, 0), new Lifetime(3));
}

// 每 tick：移动 + 让寿命递减；到期实体排队销毁
const tick = params(Query(Position, Velocity, Lifetime, Entity, Cmd())).system(
  (rows, commands) => {
    for (const [pos, vel, life, entity] of rows) {
      pos.x += vel.x;
      if (--life.remaining <= 0) commands.despawn(entity);
    }
  },
);

// 每 tick：为存活的每个实体"生成一个子弹"（spawn 命令链）
const spawnBullet = params(Query(Position, Cmd())).system((rows, commands) => {
  for (const [pos] of rows) {
    commands.spawn().with(new Position(pos.x, pos.y)).with(new Velocity(0, 1));
  }
});

const report = params(Query(Position)).system((rows) => {
  console.log('alive entities:', rows.length);
});

new App()
  .addStartupSystem(setup)
  .addSystem(tick)        // 注意顺序：tick 先跑（生成子弹在其后）
  .addSystem(spawnBullet)
  .addSystem(report)
  .run(4);
```

预期输出（示意）：

```
alive entities: 3   ← tick0 末尾只剩第 1 帧的存活者 + 第 2 帧新子弹，见注释
...
```

（想观察精确演化，请运行仓库 `examples/03-commands.ts` 与 `examples/05-despawn.ts`。）

## 小结

- `Commands` 延迟执行结构性变更：`spawn`/`despawn`/`insert`/`remove`/`insertResource`/`removeResource`；
- 通过 `Cmd()` 注入；队列在**每个 Stage 结束后**统一应用；
- `spawn()` 返回 `SpawnBuilder`，支持 `.with(...)` 链式挂组件、`.onSpawn(...)` 取新句柄；
- 要销毁/操作实体必须先有它的 `Entity`（查询 fetch `Entity` 或 `systemWithWorld`）；
- 启动阶段没有并发顾虑，可直接 `world.spawnWith(...)`。
