# 04 · 查询与过滤器

查询（Query）是 ECS 最重要的读路径：**告诉框架"我要拥有哪些组件的实体"，框架高效地把它们找出来**。PureEcs 的查询引擎：

- 从**组件最少**的存储（SparseSet）出发遍历，再用其余存储做存在性校验；
- 每个 `Query` 描述符会被预编译成 `QueryEngine`，并按 World 缓存 storage 引用（`storageVersion` 变更时自动失效重建）；
- 提供类型安全、自动推断的 API：`params(Query(...)).system(...)`。

## Query 基础：一次查询该写在哪

查询需要包裹在 `params(Query(...))` 里（或在系统外预构建 engine 手动遍历）。日常 99% 的用法：

```ts
params(Query(Position, Velocity)).system((rows) => {
  for (const [pos, vel] of rows) {
    pos.x += vel.x;
  }
});
```

其中：

- `Query(...)` 里的普通 class 是要 **fetch（拉取）** 的组件；
- fetch 1 个组件 → 回调拿到 `Comp[]`；
- fetch 2~4 个组件 → 回调拿到 `[CompA, CompB][]`，**同一元组内的组件必然来自同一个实体**（AND 联结）。

## 联结 vs 独立查询（回顾）

```ts
// Query(A, B)：一个元组 = 一个实体同时有 A 和 B —— 联结语义
params(Query(Position, Velocity)).system((rows) => { /* ... */ });

// params(A, B)：A、B 各自独立成组，没有实体对应关系 —— 不要按下标配对！
params(Position, Velocity).system((positions, velocities) => { /* ... */ });
```

## 把 Entity 放进结果：拿到实体句柄

把内置的 `Entity` 当作 fetch 之一，元组里就会带上实体本身：

```ts
import { App, params, Query, Entity } from 'pureecs';

const sys = params(Query(Position, Entity)).system((rows) => {
  // rows: [Position, Entity][]
  for (const [pos, entity] of rows) {
    console.log(`${entity.toString()} at (${pos.x}, ${pos.y})`);
    // 需要增删组件、销毁实体等结构化操作？
    // 在 system 里应当用延迟命令（见 docs/05），而非直接改 World
  }
});
```

> 为什么需要 `Entity`？组件 CRUD（增删组件、销毁实体）都需要实体句柄，而普通的 `Query` 只返回组件值。查询里显式要 `Entity` 是最安全的方式。只拿到裸组件数组时，也可以换用 `systemWithWorld`（见 docs/03）拿到对齐的实体 ID 列表，再 `world.getEntityById(id)`。

## 过滤器：With / Without / Added / Changed

过滤器作为 `Query()` 的**尾部参数**传入：

| 过滤器 | 含义 |
| --- | --- |
| `With(X)` | 该实体必须还拥有 `X` |
| `Without(X)` | 该实体必须**不**拥有 `X` |
| `Added(X)` | `X` 是**本 tick 刚被添加**到该实体 |
| `Changed(X)` | `X` 本 tick 被标记修改过（见变更追踪） |

### With / Without：按"有没有另一个组件"筛选

```ts
// 所有"敌人"，即拥有 Position 且带 Enemy 标签、但没有 Player 标签
const enemyPositions = params(Query(Position, With(Enemy), Without(Player))).system((rows) => {
  for (const [pos] of rows) {
    // 只有 Enemy & !Player 的实体
  }
});
```

引擎会把这些过滤器当成额外约束做短路判断。其中 `With()` 还能充当**候选集**（因为它提供的是"正集合"），让遍历起点可能更小；`Without()` 只能做排除。

### Added / Changed：本 tick 的"新"与"改"

```ts
// 播放音效：只对"刚刚获得 Health 组件"的实体触发
params(Query(Health, Added(Health))).system((rows) => {
  for (const [hp] of rows) {
    playSfx('heal'); // 本 tick 才生效
  }
});

// 重绘：只对位置被改过的实体
params(Query(Position, Changed(Position))).system((rows) => {
  for (const [pos] of rows) markDirty(pos);
});
```

重要语义：

- **`Added`/`Changed` 每次 `update()` 结束都会被清除**，因此它们的窗口是一个 tick（系统执行期间 -> tick 末尾清零）；
- `Added` 由插入组件触发（`insertComponent`/`spawnWith`/`Commands.insert` 等）；
- `Changed` 只在**通过 `Mut` / `ResourceMut` 的 `.get()` 写**或使用 `getComponentMut` 时触发。直接拿普通引用改字段**不会**被追踪（见 docs/07）；
- 如果你在一个系统里写了 `Changed(X)`，又在更早的系统里用 `Mut` 改了 `X`，那么该 tick 后面系统就能看到 `Changed`。

### 过滤器同时使用

```ts
// 新增的敌人：既带 Enemy，本 tick 又新增了 Health
params(Query(Position, Health, With(Enemy), Added(Health))).system((rows) => {
  // ...
});
```

### 兼容语法：过滤器作为首参

老风格支持把 `With/Added/Changed` 放第一位（此时它兼任 fetch 与 filter），等价写法：

```ts
// 等价于 Query(Position, With(Enemy)) —— 返回带 Enemy 的 Position
params(Query(With(Position), Without(Health))).system((positions) => {
  // positions: Position[] —— 拥有 Position 但没有 Health
});
```

```ts
// 等价于 Query(Position, Changed(Position))
params(Query(Changed(Position))).system((positions) => {
  // 只包含本 tick 被改过的 Position
});
```

> `Without` 没有这种"兼任 fetch"的能力——它没有正集合，不能作为主拉取。

## Single：只取第一个匹配实体

需要"场景里唯一的一个 X"（主相机、唯一玩家、全局唯一实体）时用 `Single()`。它只返回第一个匹配实体的组件，**单值**（不是数组）：

```ts
// 取唯一玩家的 Position（没有则 undefined）
const sys = params(Query(Position, With(Player)), Single(Position)).system((rows, playerPos) => {
  // rows: Position[]（所有带 Position 的）
  // playerPos: Position | undefined —— 第一个带 Player 的实体的 Position
});
```

更精确一点——玩家与摄像机都从"拥有 Player 组件"的实体来取：

```ts
const follow = params(
  Query(Position, With(Player)),
  Single(Position, With(Player)),      // 单独一次查询：第一个带 Player 的
).system((allPositions, playerPosition) => {
  if (playerPosition) {
    // camera follows playerPosition
  }
});
```

`Single` 语义：

- `Single(A)` → `A | undefined`
- `Single(A, B)` → `[A, B] | undefined`（多 fetch 返回元组）
- 若没有匹配实体，注入 `undefined`，请做空判断；
- 它执行的是一次**独立遍历**，因此别把它放在每帧 hot path 里滥用（每次 `.system()` 调用都会重新查询）。

## Query 的迭代细节（进阶）

了解这些有助于写出可预期的代码：

- **最小候选集遍历**：引擎遍历"匹配实体最少"的那个存储。比如 `Query(Position, With(Rare))` 若 `Rare` 实体远少于 `Position`，会以 `Rare` 为起点；
- **存储引用缓存**：`QueryEngine` 记录 per-World 的 storage 引用；只有在世界新增了"从未见过的组件类型"导致 `storageVersion` 变化时才重新解析。也就是说同一次系统运行中重复查询代价很低；
- `systemForEach`（docs/03）的 1~3 fetch 快路径**不分配中间数组/元组**，是最快方式；
- 回调内获得的组件是 dense 数组里的真实引用，修改会立即反映到世界——但若随后在该 tick 有实体被 despawn/remove，引用仍可能被复用到别处（swap-remove 语义），所以**不要在回调外长期持有引用**。

## 在系统外手动查询

虽然系统内用 `params` 更惯用，但任何地方都能直接对 `World` 查询：

```ts
import { World, QueryEngine, With, Changed } from 'pureecs';

const world = new World();
// ...生成若干实体...

// 方式一：简单查询迭代器（返回 [entityId, components][]）
for (const [id, comps] of world.query(Position, Health)) {
  console.log(id, comps[0], comps[1]);
}

// 方式二：预构建 engine 复用（适合循环里反复查）
const engine = new QueryEngine([Position, Health], [With(Enemy), Changed(Health)]);
engine.forEach(world, (entityId, components) => {
  // ...
});
```

> `World` 的 `query()` 每次都会 new 一个 `QueryEngine`，适合低频调用；高频场景应复用预构建的 engine。注意传入的顺序即元组顺序。

## 完整可运行示例

```ts
import { App, World, params, Query, Single, With, Without, Added, Changed } from 'pureecs';

class Position { constructor(public x = 0, public y = 0) {} }
class Velocity { constructor(public x = 0, public y = 0) {} }
class Health   { constructor(public hp = 100) {} }
class Player   {}
class Enemy    {}

function setup(world: World) {
  world.spawnWith(new Position(0, 0), new Velocity(2, 0), new Player());
  world.spawnWith(new Position(5, 0), new Health(30), new Enemy());
  world.spawnWith(new Position(9, 0), new Health(10), new Enemy());
}

// 1. 移动全部有 Position+Velocity 的实体
const move = params(Query(Position, Velocity)).systemForEach((pos, vel) => {
  pos.x += vel.x;
});

// 2. 对"新增 Health 的 Enemy"自动扣血一次（演示 Added 只在一 tick 内生效）
const poison = params(Query(Health, With(Enemy), Added(Health))).system((rows) => {
  for (const [hp] of rows) hp.hp -= 5;
});

// 3. 结算：无 Player 保护、且本 tick 位置被改过的 Enemy 额外受创
//    （组合 With / Without / Changed，演示一个 Query 上挂多个过滤器）
const combat = params(
  Query(Health, With(Enemy), Without(Player), Changed(Position)),
).system((rows) => {
  for (const [hp] of rows) hp.hp -= 15;
});

// 4. 相机跟随唯一玩家：Single 拿到的就是第一个"带 Player 的 Position"
const camera = params(
  Query(Position, With(Player)),
  Single(Position, With(Player)),
).system((all, playerPos) => {
  if (playerPos) console.log('camera at', playerPos.x);
});

new App()
  .addStartupSystem(setup)
  .addSystem(move)
  .addSystem(poison)
  .addSystem(combat)
  .addSystem(camera)
  .run(2);
```

完整可编译版本请参考仓库 `examples/02-query-filters.ts`。

## 小结

- `Query(A, B)` 联结出**同实体**多组件；`With/Without/Added/Changed` 作为尾部过滤器；
- 需要实体句柄就 fetch `Entity`；要"唯一实体"用 `Single()`；
- 独立裸组件参数与联结查询不要混淆；
- `Added/Changed` 只在**一个 tick**内有效；
- 引擎自动选最小候选集遍历，并缓存 storage，可放心在系统里频繁查询。
