# 01 · 概述与快速开始

## PureEcs 是什么

PureEcs 是一个受 [Bevy](https://bevyengine.org/) 启发的 **TypeScript ECS**（Entity-Component-System，实体-组件-系统）框架：

- **纯 TypeScript** 实现，**零运行时依赖**，按需树摇（ESM）；
- **强类型推断**：基于泛型 `params()` 的参数描述符，系统的入参完全由编译器推导；
- **数据驱动**：逻辑与数据分离，天然适合游戏、模拟器、编辑器等场景；
- **缓存友好**：组件存储在 SparseSet 中，遍历采用最小组件集（最小组件集合）驱动，避免无谓的逐实体检查。

### ECS 三个核心概念

| 概念 | 一句话 | 对应 API |
| --- | --- | --- |
| **Entity（实体）** | 世界中一个可唯一标识的"事物"，本身不携带任何数据 | `world.spawn()` / `Entity` |
| **Component（组件）** | 挂在实体上的纯数据片段，只是一个普通 class | `new Position(0, 0)` |
| **System（系统）** | 读取、修改一批组件/资源的函数 | `params(Query(...)).system(fn)` |

```ts
// 通俗理解
// Entity 是"对象 ID"，Component 是"数据字段"，System 是"遍历并处理数据的函数"。
```

### 为什么需要 ECS

与传统 OOP（对象自带方法）相比，ECS 把"对象"拆成两个正交维度：

- **实体**：轻量 ID（本项目使用代际索引，见 `docs/02`）；
- **组件**：纯数据，按类型存放在连续存储中，遍历时缓存友好；
- **系统**：按"我关心哪些组件"来筛选实体，而不是按对象类型。

这使得"给所有带 `Velocity` 的实体加速"这类横切逻辑写起来非常自然，也便于通过系统调度（`docs/08`）精确控制执行顺序。

## 安装

PureEcs 以 `pureecs` 名称发布（当前版本见仓库 `package.json`）。在你自己的项目里：

```bash
# npm
npm install pureecs

# pnpm
pnpm add pureecs
```

如果你 clone 的是本仓库，也可以直接引用源码入口 `src/index.ts`（仓库内所有 `examples/` 均如此导入）：

```ts
import { App, World, params, Query } from './src/index';
```

## 最快路径：一个最小 App

```ts
import { App, World, params, Query } from 'pureecs';

// 1. 组件 = 普通 class
class Position {
  constructor(public x = 0, public y = 0) {}
}
class Velocity {
  constructor(public x = 0, public y = 0) {}
}

// 2. 系统 = 普通函数。想读哪些数据，就"声明"哪些参数
const movement = params(Query(Position, Velocity)).system((rows) => {
  // rows: [Position, Velocity][] —— 每个元素都来自同一个实体（AND 联结）
  for (const [pos, vel] of rows) {
    pos.x += vel.x;
    pos.y += vel.y;
  }
});

const report = params(Query(Position)).system((positions) => {
  for (const [pos] of positions) {
    console.log(`(${pos.x}, ${pos.y})`);
  }
});

// 3. 用 App 组装：启动系统 + 每帧系统
new App()
  .addStartupSystem((world) => {
    // 启动时只跑一次：生成两个实体
    world.spawnWith(new Position(0, 0), new Velocity(1, 2));
    world.spawnWith(new Position(10, 10), new Velocity(0, -1));
  })
  .addSystem(movement)
  .addSystem(report)
  .run(3); // 连跑 3 个 tick（帧）
```

输出：

```
(3, 6)
(10, 8)
(6, 12)
(10, 7)
(9, 18)
(10, 6)
```

> `movement` 与 `report` 都在默认的 `Stages.Update` 阶段，注册顺序即执行顺序。

## App 与 World：两个层次

PureEcs 提供两个入口对象：

| 对象 | 角色 | 典型用途 |
| --- | --- | --- |
| `World` | 持有实体、组件、资源、事件、命令队列与调度器的"宇宙" | 直接操作数据的底层 API |
| `App` | 顶层门面，内含 `world`，提供链式构建（`.addSystem(...)`、`.insertResource(...)`） | 组装插件与系统后统一 `run()` |

实际运行时只有一个循环 `App`（或 `World`）的 `update()`：

```
┌─────────────────────── World.update() ───────────────────────┐
│                                                              │
│  ① 首次调用：按 Startup 阶段执行所有启动系统（仅一次）         │
│  ② 依次执行每个 Stage 内的系统                                │
│     · 同 Stage 内按注册顺序 / before-after 拓扑排序          │
│     · 每执行完一个 Stage，冲刷一次 Commands（延迟命令）        │
│  ③ tick 末尾：清理变更追踪标记与事件缓冲                      │
└──────────────────────────────────────────────────────────────┘
```

关键点：

- `addStartupSystem(fn)` 注册的系统只在**第一次** `update()` 时执行；
- 系统中通过 `commands` 提交的延迟变更（`spawn`/`despawn`/`insert`…）在**每个 Stage 结束后**统一应用，因此系统执行期间世界状态是稳定的；
- 每一 tick 结束会清空"新增/修改"标记与事件，因此 **`Added`/`Changed` 过滤器与事件只在一个 tick 内有效**（详见对应章节）。

## App 生命周期

```ts
const app = new App();

app
  .addStartupSystem(setup)          // 启动系统
  .addSystem(update)                // 普通系统（默认 Stages.Update）
  .addSystem(Stages.PostUpdate, ui) // 指定阶段
  .insertResource(new Score(0))     // 插入资源
  .addEvent<Died>()                 // 注册事件类型
  .addPlugin(new InputPlugin());    // 挂载插件（见 docs/09）

app.run();                 // 跑一个 tick
app.run(120);              // 连续跑 120 个 tick
// 之后如需释放插件持有的外部资源（例如输入插件的 DOM 监听器）：
app.destroy();
```

手动循环示例（配合 requestAnimationFrame）：

```ts
const app = new App().addSystem(movement).addSystem(render);

function frame() {
  app.update();
  requestAnimationFrame(frame);
}
requestAnimationFrame(frame);
```
