# 12 · 状态管理（State / NextState / 生命周期）

`State` 用于保存应用的离散流程，例如菜单、游戏中、暂停或加载阶段。每个状态机由 `defineState` 定义，并生成带类型的成员对象；不同定义可以在同一个 `World` 内独立存在。

```ts
import {
  App, World, defineState, State, NextState, OnEnter, OnExit, OnTransition, inState, system,
} from 'pureecs';

const Screen = defineState({
  Menu: { initial: true },
  Playing: {},
});

function setupMenu() { /* create menu entities */ }
function cleanupMenu() { /* remove menu entities */ }
function beginGame() { /* create gameplay entities */ }
function updateMenu() { /* menu input and animation */ }
function updateGame() { /* gameplay */ }

const app = new App()
  .addState(Screen)
  .addSystem(OnEnter(Screen.Menu), setupMenu)
  .addSystem(OnExit(Screen.Menu), cleanupMenu)
  .addSystem(OnTransition(Screen.Menu, Screen.Playing), beginGame)
  .addSystemConfig(system(updateMenu).runIf(inState(Screen.Menu)))
  .addSystemConfig(system(updateGame).runIf(inState(Screen.Playing)));
```

## 读取与切换

在系统中读取当前状态或请求下一状态：

```ts
function startGame(world: World): void {
  if (world.state(Screen).get() === Screen.Menu) {
    world.nextState(Screen).set(Screen.Playing);
  }
}
```

系统中可通过 `params(State(Screen))` 读取当前状态，通过 `params(NextState(Screen))` 请求切换；后者与 Bevy 的 `NextState<S>` 用法一致。

请求不会立即改变当前状态。调度器在 `Stages.PreUpdate` 之后运行 `Stages.StateTransition`：

```
OnExit(current) -> OnTransition(current, next) -> 更新 State -> OnEnter(next)
```

生命周期系统执行完后，当前 tick 才继续进入 `Stages.Update`。因此在 `OnExit` 与 `OnTransition` 中，`inState` 仍匹配旧值；在 `OnEnter` 以及后续普通系统中，它匹配新值。

首次进入初始状态也会触发相应的 `OnEnter` 系统一次。对当前值重复请求不会触发生命周期系统。一次 tick 内多次调用 `set()` 时，最后一次请求生效；在生命周期系统中发出的新请求会留到下一个 `StateTransition` 点处理。

## DespawnOnExit

给状态专属实体附加 `DespawnOnExit` 组件，可在离开状态时自动销毁它。例如菜单 UI 在离开菜单后不应继续存在：

```ts
const menu = world.spawnWith(
  new MenuUi(),
  new DespawnOnExit(Screen.Menu),
);
```

匹配的实体在该状态的所有 `OnExit` 系统完成后、`OnTransition` 之前立即销毁。标记的状态机定义和成员都必须匹配，因此 `new DespawnOnExit(Screen.Playing)` 不会在退出 `Screen.Menu` 时被删除。

## 条件与多个状态机

`inState(StateType, value)` 返回一个可用于 `system(...).runIf(...)` 的条件，也可以和其它 `runIf`、`SystemSet` 条件组合。每个状态机都有自己的 resource class：

```ts
const Pause = defineState({
  Running: { initial: true },
  Paused: {},
});

app
  .addState(Pause)
  .addSystemConfig(system(simulate).runIf(inState(Screen.Playing)))
  .addSystemConfig(system(simulate).runIf(inState(Pause.Running)));
```

这里两个条件分别检查 `ScreenState` 和 `PauseState`，互不覆盖。重复初始化同一个状态 class 会抛出错误，以免无意替换正在运行的状态机。
