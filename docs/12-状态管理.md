# 12 · 状态管理（State / NextState / 生命周期）

`State` 用于保存应用的离散流程，例如菜单、游戏中、暂停或加载阶段。它是一个资源，因此每个状态机都用一个继承 `State<S>` 的 class 标识；不同 class 可以在同一个 `World` 内独立存在。

```ts
import {
  App, World, State, OnEnter, OnExit, OnTransition, inState, system,
} from 'pureecs';

type Screen = 'menu' | 'playing';
class ScreenState extends State<Screen> {}

function setupMenu() { /* create menu entities */ }
function cleanupMenu() { /* remove menu entities */ }
function beginGame() { /* create gameplay entities */ }
function updateMenu() { /* menu input and animation */ }
function updateGame() { /* gameplay */ }

const app = new App()
  .initState(ScreenState, 'menu')
  .addSystem(OnEnter(ScreenState, 'menu'), setupMenu)
  .addSystem(OnExit(ScreenState, 'menu'), cleanupMenu)
  .addSystem(OnTransition(ScreenState, 'menu', 'playing'), beginGame)
  .addSystemConfig(system(updateMenu).runIf(inState(ScreenState, 'menu')))
  .addSystemConfig(system(updateGame).runIf(inState(ScreenState, 'playing')));
```

## 读取与切换

在系统中读取当前状态或请求下一状态：

```ts
function startGame(world: World): void {
  if (world.getState(ScreenState).get() === 'menu') {
    world.getNextState(ScreenState).set('playing');
  }
}
```

`world.getResource(ScreenState)` 也能获得同一个 `State<Screen>` 资源，因此可以用 `params(Res(ScreenState))` 注入读取。`State.set(next)` 与 `world.getNextState(ScreenState).set(next)` 等价；后者与 Bevy 的 `NextState<S>` 用法一致。

请求不会立即改变当前状态。调度器在 `Stages.PreUpdate` 之后运行 `Stages.StateTransition`：

```
OnExit(current) -> OnTransition(current, next) -> 更新 State -> OnEnter(next)
```

生命周期系统执行完后，当前 tick 才继续进入 `Stages.Update`。因此在 `OnExit` 与 `OnTransition` 中，`inState` 仍匹配旧值；在 `OnEnter` 以及后续普通系统中，它匹配新值。

首次进入初始状态也会触发相应的 `OnEnter` 系统一次。对当前值重复请求不会触发生命周期系统。一次 tick 内多次调用 `set()` 时，最后一次请求生效；在生命周期系统中发出的新请求会留到下一个 `StateTransition` 点处理。

## DespawnOnExit

给状态专属实体附加 `DespawnOnExit` 组件，可在离开状态时自动销毁它。例如菜单 UI 在离开菜单后不应继续存在：

```ts
const menu = world.spawnWith(
  new MenuUi(),
  new DespawnOnExit(ScreenState, 'menu'),
);
```

匹配的实体在该状态的所有 `OnExit` 系统完成后、`OnTransition` 之前立即销毁。标记的状态机类型和值都必须匹配，因此 `new DespawnOnExit(ScreenState, 'playing')` 不会在退出 `'menu'` 时被删除。

## 条件与多个状态机

`inState(StateType, value)` 返回一个可用于 `system(...).runIf(...)` 的条件，也可以和其它 `runIf`、`SystemSet` 条件组合。每个状态机都有自己的 resource class：

```ts
class PauseState extends State<boolean> {}

app
  .initState(PauseState, false)
  .addSystemConfig(system(simulate).runIf(inState(ScreenState, 'playing')))
  .addSystemConfig(system(simulate).runIf(inState(PauseState, false)));
```

这里两个条件分别检查 `ScreenState` 和 `PauseState`，互不覆盖。重复初始化同一个状态 class 会抛出错误，以免无意替换正在运行的状态机。
