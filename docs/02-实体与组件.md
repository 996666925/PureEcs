# 02 · 实体与组件

实体（Entity）与组件（Component）是 ECS 的两块基石。这一篇讲清楚它们是什么、如何创建/销毁、如何读写组件，以及"代际索引"为什么能避免悬空引用。

## Entity：轻量 ID

`Entity` 只是一个 `{ id, generation }` 二元组：

```ts
export class Entity {
  readonly id: number;
  readonly generation: number;
  equals(other: Entity): boolean;
  toString(): string; // 例如 "Entity(3v1)"
}
```

- `id`：实体在分配器中的槽位索引；
- `generation`（代际）：同一个槽位被复用的次数。

### 生成与销毁

```ts
import { World, Entity } from 'pureecs';

const world = new World();

// 生成（不带组件）
const e = world.spawn(); // Entity
console.log(e.toString()); // 形如 "Entity(0v0)"

// 销毁
world.despawn(e); // true
console.log(world.isAlive(e)); // false

// 销毁一个不存活/过期句柄会返回 false
world.despawn(e); // false
```

### 一次性生成并挂载初始组件

`spawnWith(...components)` 在分配实体的同时直接插入一批初始组件，避免对每个组件重复做实体存活检查，**批量初始化更快**：

```ts
class Position {
  constructor(public x = 0, public y = 0) {}
}
class Name {
  constructor(public value = '') {}
}

const player = world.spawnWith(new Position(0, 0), new Name('Player'));
// player: Entity，已携带 Position 与 Name
```

也可以分两步：

```ts
const e = world.spawn();
world.insertComponent(e, new Position(1, 2));
```

`spawnWith` 等价于 `spawn()` 后再逐个 `insertComponent`，但少了几次查表。

## 代际索引（Generational Indexing）：为什么旧句柄不会误伤新实体

实体被销毁后，其槽位会被回收并加入空闲链表。当再次 `spawn()` 时，分配器优先复用空闲槽位，但 `generation` 会自增：

```ts
const a = world.spawn();      // id=0, generation=0
world.despawn(a);             // 槽位 0 空闲，代际升至 1
const b = world.spawn();      // 复用 id=0，但 generation=1

console.log(a.equals(b));     // false（generation 不同）
console.log(world.isAlive(a)); // false —— 旧句柄已失效，安全
console.log(world.isAlive(b)); // true
```

因为 `Entity` 的相等性同时要求 `id` 与 `generation` 一致，**你手里的旧实体句柄永远不会意外操作到后来复用同一槽位的实体**。这被称为"代际索引"，是 Bevy 等现代 ECS 的标准做法。

实际编码时的收益：在异步回调、延迟命令（`docs/05`）、事件负载里持有 `Entity` 都是安全的——使用前用 `world.isAlive(entity)` 确认即可。

## Component：普通 class，无需注册

组件是**纯 TypeScript class**。框架通过 class 构造函数本身识别组件类型，因此：

- 不需要继承基类；
- 不需要装饰器；
- 不需要提前注册；
- 可以携带构造参数、默认值、方法（建议只放数据 + 少量工具方法）。

```ts
class Health {
  constructor(public current = 100, public max = 100) {}
}
class Speed {
  constructor(public value = 1) {}
}
class PlayerTag {}
```

> 内部实现使用一个 `WeakMap<ComponentClass, number>` 为每个 class 分配紧凑的数字 ID，作为存储索引。这也是为什么组件必须是 **class 而非 interface/type**——interface 在运行时不存在。

### 组件 CRUD

```ts
// 写
world.insertComponent(entity, new Health(80));

// 读（不存在时返回 undefined）
const hp = world.getComponent(entity, Health); // Health | undefined

// 判断
const has = world.hasComponent(entity, Health); // boolean

// 删
const removed = world.removeComponent(entity, Health); // 返回被删实例
```

**可变读**：`getComponent` 返回的是同一引用，直接改字段即可被读到，但若想让"修改"被变更追踪记录（`Added`/`Changed` 过滤器需要），应当使用 `getComponentMut`：

```ts
const mut = world.getComponentMut(entity, Health);
if (mut) {
  mut.get().current -= 10; // mut.get() 会标记该组件本 tick 已被修改
  // 若只想读取而不标记：mut.peek()
}
```

`Mut<T>` 与 `ResourceMut<T>` 的完整语义（`.get()` 标记、`.peek()` 不标记、何时被清理）见 `docs/07`。

### 实体同时拥有哪些组件？

`World` 内部对每个实体记录一份组件 ID 列表（`entityComponentIds`），随插入/移除同步维护。框架提供的高层 API 不直接暴露该列表，日常更推荐用**查询**（`docs/04`）按需筛选：

```ts
// 想知道某个实体身上有哪些东西，可逐个探测：
if (world.hasComponent(e, Health)) { /* … */ }
if (world.hasComponent(e, PlayerTag)) { /* … */ }
```

## 组合优于继承

同一实体可以同时携带任意组件，这正是"组合"的来源：

```ts
class Position { constructor(public x = 0, public y = 0) {} }
class Velocity { constructor(public x = 0, public y = 0) {} }
class Sprite    { constructor(public url = '') {} }
class AIController { constructor(public mode = 'patrol') {} }

// 一匹马：能走、能显示、还被 AI 控制
const horse = world.spawnWith(new Position(0, 0), new Velocity(2, 0), new Sprite('horse.png'), new AIController());

// 一个静态装饰物：只显示，不移动
const tree = world.spawnWith(new Position(5, 5), new Sprite('tree.png'));

// 一个纯逻辑单位：看不见，但会移动
const trigger = world.spawnWith(new Position(0, 0), new Velocity(0, 0), new AIController());
```

系统只关心"需要哪些组件"，因此不同种类的实体可以共享同一套系统逻辑（例如 `movement` 系统处理一切同时拥有 `Position`+`Velocity` 的实体）。

## 完整可运行示例

```ts
import { World } from 'pureecs';

class Position {
  constructor(public x = 0, public y = 0) {}
}
class Name {
  constructor(public value = '') {}
}
class Health {
  constructor(public hp = 100) {}
}

const world = new World();

// 生成实体 + 初始组件（等价于 spawn 后逐个 insert，但更快）
const player = world.spawnWith(
  new Position(0, 0),
  new Name('hero'),
  new Health(100),
);

console.log(world.isAlive(player));            // true
console.log(world.hasComponent(player, Health)); // true

// 增
world.insertComponent(player, new Name('hero-2'));
console.log(world.getComponent(player, Name)!.value); // hero-2（insert 会覆盖同名组件）

// 改（使用 Mut 以触发变更追踪）
const mut = world.getComponentMut(player, Health);
if (mut) mut.get().hp -= 25;

// 删组件
world.removeComponent(player, Health);
console.log(world.hasComponent(player, Health)); // false

// 删实体
world.despawn(player);
console.log(world.isAlive(player)); // false

// 代际安全：即使之后 spawn 复用了 id=0 的槽位，旧句柄 player 也永远失效
const newbie = world.spawn();
console.log(player.equals(newbie)); // false
console.log(world.isAlive(player)); // false
```

## 小结

- `Entity` = `id + generation`，销毁后被回收的槽位会带新代际重生，旧句柄永远安全；
- 组件是普通 class，按构造函数识别，无需注册；
- 增删改查分别用 `insertComponent` / `removeComponent` / `getComponent`(读) / `getComponentMut`(写+标记) / `hasComponent`(判断)；
- `spawnWith(...)` 适合批量初始化，性能更好；
- 世界状态的**结构变更**（spawn/despawn/insert/remove）也可以放到 `Commands` 里延迟执行，见 `docs/05`。
