# 09 · 插件机制（Plugin / PluginGroup / DefaultPlugin）

当你的项目由大量"可复用功能包"组成（物理、渲染、音效、AI、输入……）时，插件就是**装配层**的答案：一个插件把一套相关的资源、系统、Stage、事件打包，通过 `app.addPlugin(plugin)` 一键接入。

## Plugin：最小接口

插件只需实现 `build(app)` 一个方法（可选 `destroy`）：

```ts
import { App, Plugin, params, Query } from 'pureecs';

class Gravity {
  constructor(public value = 9.8) {}
}
class Position { constructor(public y = 0) {} }
class Velocity { constructor(public y = 0) {} }

class GravityPlugin implements Plugin {
  build(app: App): void {
    app.insertResource(new Gravity());            // 1) 提供资源
    app.addSystem(applyGravity);                  // 2) 注册系统
  }
}

const applyGravity = params(Query(Velocity)).system((rows) => {
  for (const [vel] of rows) vel.y -= 1;
});
```

使用：

```ts
new App().addPlugin(new GravityPlugin()).run(60);
```

`build(app)` 里能调用 App 的一切装配方法：

| 能力 | 示例 |
| --- | --- |
| 插入资源 | `app.insertResource(new Gravity(9.8))` |
| 注册系统（可带 Stage/排序） | `app.addSystem(Stages.Update, sys)` / `app.addSystemConfig(config)` |
| 注册启动系统 | `app.addStartupSystem(setup)` |
| 注册事件 | `app.addEvent(PlayerDied)` |
| 插入自定义 Stage | `app.addStageBefore(MyStage, Stages.Update)` |
| 挂载子插件 | `app.addPlugin(new PhysicsCorePlugin())` |
| 读取资源做条件注册 | `if (app.world.hasResource(Headless)) …` |

## 插件之间的协作约定

一个工程良好实践：

1. **插件只认资源/事件，不认其它插件的实现细节**。两个插件通过 `Res`/`Event`/组件类型"协议"协作；
2. 插件把**需要的资源**在 `build` 里插入，把**不需要外部可见的行为**封装起来；
3. 插件之间如需顺序，各自在自己的阶段/集合内声明（docs/08）。

示例：两个互相"不认识"的插件通过事件协作

```ts
class KilledEvent { constructor(public entityId = 0) {} }

class DamagePlugin implements Plugin {
  build(app: App): void {
    app.addEvent(KilledEvent);
    app.addSystem(spawnDamageNumbers);   // 逻辑插件：发 KilledEvent
  }
}
class SfxPlugin implements Plugin {
  build(app: App): void {
    // 只订阅事件，不知道 DamagePlugin 是谁
    app.addSystem(playKillSound);        // EventReader(KilledEvent)
  }
}
```

## PluginGroup：打包与嵌套

`PluginGroup` 把多个插件合成一个"组合插件"，支持链式 `.add()`，本身也实现 `Plugin` 接口，因此可以**嵌套**：

```ts
import { PluginGroup } from 'pureecs';

// 把 2D 游戏基础能力打包：
const platformerCore = new PluginGroup()
  .add(new InputPlugin())          // 键盘鼠标（docs/10）
  .add(new GravityPlugin())
  .add(new CameraPlugin());

// 组合进更高层：
const fullGame = new PluginGroup()
  .add(new DefaultPlugin())        // Time + 帧时钟
  .add(platformerCore);            // 直接 add 组合插件

new App().addPlugin(fullGame).update();
```

组合插件的 `destroy()` 会**逆序**销毁内部插件（后加的插件先销毁）。

## destroy 与生命周期

`Plugin` 的 `destroy(app)` 用于释放插件占用的**外部资源**（DOM 监听、定时器、WebSocket……）。调用时机：

```ts
const app = new App().addPlugin(new InputPlugin()); // InputPlugin 在 DOM 上挂了监听器

app.run(120);

// 应用结束/切场景时释放：
app.destroy();   // 逆序调用所有插件的 destroy()
```

- `App.destroy()` 会把 `destroyed` 置位，此后任何 `update/run/addSystem` 都会抛 `App has been destroyed`；
- `InputPlugin` 等内置插件已实现 `destroy`，会自动移除 DOM 事件监听（见 docs/10）。

```ts
class NetPlugin implements Plugin {
  private cleanup: (() => void) | null = null;
  build(app: App): void {
    const handler = () => { /* 收包处理 */ };
    window.addEventListener('message', handler);
    this.cleanup = () => window.removeEventListener('message', handler);
  }
  destroy(): void {
    this.cleanup?.();
    this.cleanup = null;
  }
}
```

## DefaultPlugin：开箱即用的"帧时钟"

`DefaultPlugin` 是最常用的内置插件，等价于：

```ts
// 它的 build 做两件事：
app.insertResource(new Time());                      // 提供全局 Time 资源
app.addSystem(Stages.First, createTimeSystem());     // 每帧用真实墙钟推进
```

```ts
import { App, DefaultPlugin } from 'pureecs';

const app = new App().addPlugin(new DefaultPlugin());
// 之后任何系统都能 Res(Time) 拿到帧 delta/elapsed（docs/07）
```

手动等价写法（不需要整包引入时）：

```ts
import { App, Time, createTimeSystem, Stages } from 'pureecs';

new App()
  .insertResource(new Time())
  .addSystem(Stages.First, createTimeSystem());
```

> `createTimeSystem()` 返回一个系统，内部用 `Date.now()` 计算真实帧间隔并 `time.update(delta)`；注册在 `Stages.First` 保证其它系统读到的 `Time.delta` 是"本帧"的值。

## 内置插件总览

| 插件 | 提供的资源/能力 | 使用 |
| --- | --- | --- |
| `DefaultPlugin` | `Time` + 每帧墙钟推进系统 | `app.addPlugin(new DefaultPlugin())` |
| `InputPlugin` | `KeyboardInput`、`MouseInput` 等 + DOM 监听/销毁 | 见 docs/10 |
| 自定义 `PluginGroup` | 任意组合 | `app.addPlugin(group)` |

## 编写插件的检查清单

- [ ] `build(app)` 幂等且不依赖注册顺序；
- [ ] 系统需要的资源在 build 内插入（否则运行期 `Res` 抛"missing"）；
- [ ] 需要与外界协作时，通过**事件/资源/组件协议**而非函数引用；
- [ ] 若占用 DOM/定时器等外部资源，实现 `destroy`；
- [ ] 需要运行时开关时，把资源（如 `Paused`）暴露出来由游戏逻辑控制。

## 可运行示例

```ts
import { App, Plugin, PluginGroup, DefaultPlugin, Time, params, Res } from 'pureecs';

class SpawnRate { constructor(public perSecond = 2) {} }

// ── 小插件 1：每秒生成事件计数 ──
class SpawnerPlugin implements Plugin {
  build(app: App): void {
    app.insertResource(new SpawnRate(2));
    app.addSystem(spawnLogic);
  }
}
const spawnLogic = params(Res(SpawnRate), Res(Time)).system((rate, time) => {
  // 用 time.delta 做“每秒 rate 个”的均匀生成……（真实生成用 commands，见 docs/05）
  console.log('delta', time.delta, 'rate', rate.perSecond);
});

// ── 组合 ──
const group = new PluginGroup()
  .add(new DefaultPlugin())
  .add(new SpawnerPlugin());

const app = new App()
  .addPlugin(group)
  .update();        // 跑一个 tick 即可看到时间系统在工作
app.destroy();      // 需要时释放
```

## 小结

- `Plugin` = `{ build(app) }`（可选 `destroy(app)`），把资源/系统/事件/Stage 打包；
- `PluginGroup.add(...)` 可组合、可嵌套；
- `App.destroy()` 逆序调用插件 `destroy()`，用于释放 DOM 监听等外部资源；
- `DefaultPlugin` 提供 `Time` 资源 + 墙钟驱动系统（`Stages.First`）；
- 插件间用"资源/事件协议"解耦是长期维护的关键。
