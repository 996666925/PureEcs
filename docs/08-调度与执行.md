# 08 · 调度与执行（Stages / 排序 / SystemSet）

系统多起来之后，"谁先谁后"就至关重要：移动系统必须跑在渲染系统之前，输入采样又必须跑在移动之前……PureEcs 提供了一套**带阶段（Stage）与排序约束（before/after）**的调度器，采用 Bevy 风格的方案。

## 一次 update 的完整时间线

回顾 docs/01 的循环，现在展开到细节：

```
World.update()
│
├─（仅首次）Startup 阶段：执行所有启动系统
│     启动系统期间产生的 Commands 在 Startup 结束后统一 apply
│
├─ Update 主循环，按固定顺序执行各 Stage：
│   Stages.First
│   Stages.PreUpdate
│   Stages.StateTransition  ← 提交 NextState，并运行 OnExit/OnTransition/OnEnter
│   Stages.Update        ← 默认 addSystem 落在这里
│   Stages.PostUpdate
│   Stages.Last
│        │ 每个 Stage 内部：所有系统按“注册顺序 + before/after 拓扑排序”执行
│        ▼ Stage 全部系统执行完 → Commands.apply()
│
├─ tick 末尾：ChangeTrackers.clear() + 所有事件通道 clear()
└─ 结束
```

两个反复出现的执行约定：

1. **Commands 在每个 Stage 结束后统一应用**（docs/05）；
2. **变更追踪与事件在每个 tick 末尾清空**（docs/07 / docs/06）。

## Stage：粗粒度"时段"

内置 Stage 常量（`Stages`）：

```ts
Stages.Startup     // 仅在第一次 update 时执行
Stages.First       // 主循环最前（适合默认时间推进：见 DefaultPlugin）
Stages.PreUpdate   // 输入采样等“准备”逻辑
Stages.StateTransition // 状态切换与生命周期系统（由 State 自动驱动）
Stages.Update      // 默认阶段：不指定 Stage 时所有系统都落在这里
Stages.PostUpdate  // 渲染、结算等“收尾”
Stages.Last        // 主循环最后（UI、销毁清理）
```

用 `App.addSystem` / `World.addSystem` 指定阶段：

```ts
import { App, Stages } from 'pureecs';

app
  .addSystem(Stages.First, updateTime)       // 时间推进最早
  .addSystem(Stages.PreUpdate, readInput)    // 输入第二早
  // StateTransition 在这里由状态系统自动执行
  .addSystem(moveEntities)                   // 不写 Stage → Stages.Update
  .addSystem(Stages.PostUpdate, render)      // 渲染最后
  .run(1);
```

重载签名：

```ts
addSystem(fn)                      // Stages.Update
addSystem(stage, fn)               // 指定阶段
addSystem(stage, fn, { after: [...], before: [...] }) // 指定阶段 + 排序
addSystemConfig(config)            // 已构建的 SystemConfig / SystemBuilder
```

### 自定义 Stage

内置 7 个不够时，自己 `new Stage('名字')`：

```ts
import { Stage, Stages } from 'pureecs';

const PhysicsStage = new Stage('Physics');
const AiStage = new Stage('AI');

const app = new App()
  .addStageBefore(PhysicsStage, Stages.Update)   // 插在 Update 之前
  .addStageAfter(AiStage, PhysicsStage)          // 插在 Physics 之后
  .addSystem(PhysicsStage, integratePhysics)
  .addSystem(AiStage, runAi);
```

- `World/App.addStageBefore(newStage, before)`、`addStageAfter(newStage, after)` 控制插入点；
- 直接 `addSystem(自定义Stage, fn)` 且该 Stage 尚未加入调度时，会自动把它插到 `Update` **之前**；
- 如果顺序约束只在一批同阶段系统之间，优先用 Stage 还是 before/after？——**细粒度排序用 before/after，粗粒度分区用 Stage**。

## 细粒度排序：before / after

同一 Stage 内，用函数引用来声明先后：

```ts
import { App, system, Stages } from 'pureecs';
import { params, Query } from 'pureecs';

function applyDamage(world: World) { /* ... */ }
function killDead(world: World) { /* ... */ }

// 方式一：App 重载的 ordering
app.addSystem(applyDamage);
app.addSystem(Stages.Update, killDead, { after: [applyDamage] });

// 方式二：SystemBuilder 链式（更可读，推荐）
app.addSystemConfig(
  system(applyDamage).inStage(Stages.Update),       // .startup() 等价于 inStage(Startup)
);
app.addSystemConfig(
  system(killDead).after(applyDamage),              // 必须在 applyDamage 之后
);
```

### SystemBuilder 全能力

```ts
import { system, Stages, SystemSet } from 'pureecs';

// 主要链式方法：
system(fn)
  .inStage(Stages.Update)     // 指定阶段
  .before(otherFn)            // 在 otherFn 之前
  .after(otherFn)             // 在 otherFn 之后
  .runIf((world) => cond)     // 条件满足才执行（每 tick 判定）
  .enabled(false)             // 彻底禁用（保留在调度里，随时可再启用）
  .inSet(mySet)               // 加入共享条件集
  .beforeSet(mySet)           // 在集合所有系统之前
  .afterSet(mySet)            // 在集合所有系统之后
  .startup()                  // 快捷 .inStage(Stages.Startup)
  .build();                   // 产出 SystemConfig，交给 addSystemConfig
```

> `before/after` 只对**同一 Stage 内**的目标生效（拓扑排序按 stage 分组进行）。跨阶段想排序，请移动系统到合适的 Stage。

### 循环依赖检测

同阶段 `before/after` 构成环时，调度器抛出 `CircularDependencyError`，并带上环里的函数名：

```
Circular dependency detected in system ordering: a -> b -> a
```

调试提示：检查你对该阶段所有系统的 before/after 声明是否自洽。

## SystemSet：给一组系统打标签

`SystemSet` 用于**成批管理**系统：给它们共享一个开关/条件，并让其它系统可以相对整个集合排序。

```ts
import { App, system, SystemSet, Stages } from 'pureecs';

// 1) 建集合 + 设置共享行为
const DebugSet = new SystemSet('Debug')
  .enabled(false)                     // 默认关闭
  .runIf((world) => world.hasResource(DebugFlag)); // 条件也生效

// 2) 把系统放进集合
app.addSystemConfig(
  system(drawFps).inStage(Stages.PostUpdate).inSet(DebugSet),
);
app.addSystemConfig(
  system(drawWireframe).inStage(Stages.PostUpdate).inSet(DebugSet),
);

// 3) 其它系统可以相对整个集合排序
app.addSystemConfig(
  system(clearScreen)
    .inStage(Stages.PostUpdate)
    .beforeSet(DebugSet),             // 先清屏，再画调试信息
);
```

`SystemSet` 支持：

- `new SystemSet(label)` 创建；
- `.enabled(bool)` 全局开关（`shouldRun` 先查它）；
- `.runIf((world) => boolean)` 追加条件（全部满足才执行集合内系统）；
- `SystemBuilder.inSet/set.beforeSet/afterSet` 关联与排序。

> 条件判定顺序：`config.enabled === false` → `config.runIf` 全真 → 所属所有 `set.shouldRun()`（集合 enabled + 条件）。集合内系统的自身 runIf 同样参与 `shouldRun` 的 `every` 判定。

## runIf / enabled：运行时开关

```ts
import { App, system, World, params, Query, Res } from 'pureecs';

class Paused {}
class GameConfig { constructor(public debug = false) {} }

const logPosition = params(Query(Position)).system((rows) => {
  for (const [pos] of rows) console.log(pos.x);
});

new App()
  .insertResource(new GameConfig())
  // 只有暂停时才打印（每 tick 执行前判断）
  .addSystemConfig(
    system(logPosition).runIf((world: World) => world.hasResource(Paused)),
  )
  // 也可以组合多个条件：全部为真才运行
  .addSystemConfig(
    system(logPosition)
      .runIf((world) => world.hasResource(Paused))
      .enabled(false)   // 先硬关闭，需要时由代码置 true
  );
```

- 条件的 `world` 参数使你可以读任何资源/世界状态做判断；
- `enabled(false)` 用于"保留但停用"的系统，非常适合调试工具；
- 注意 `runIf` 每 tick 执行前判定，不执行时也**不会产生副作用**（系统 fn 压根不调用）。

## 一个完整的调度编排示例

```ts
import { App, World, system, Stages, SystemSet, Time, createTimeSystem, params, Query, Res, ResMut } from 'pureecs';

class Position { constructor(public x = 0, public y = 0) {} }
class Velocity { constructor(public x = 0, public y = 0) {} }
class Health { constructor(public hp = 100) {} }
class GameConfig { constructor(public paused = false) {} }
class DebugFlag {}

// ── 各系统 ──
function applyInput(world: World) { /* 读输入，写 Velocity */ }
const physics = params(Query(Position, Velocity)).systemForEach((pos, vel) => {
  pos.x += vel.x;
});
const damageTick = params(Query(Health), Res(GameConfig)).system((rows, cfg) => {
  if (!cfg.paused) for (const [hp] of rows) hp.hp -= 1;
});
function render(world: World) { /* 画到屏幕 */ }

const DebugUiSet = new SystemSet('DebugUi').enabled(false);

const app = new App()
  // 时间推进第一（DefaultPlugin 在 First 注册了 createTimeSystem，此处等价手动写法）
  .insertResource(new Time())
  .addSystem(Stages.First, createTimeSystem())
  // 输入准备
  .addSystem(Stages.PreUpdate, applyInput)
  // 主逻辑：物理在扣血前
  .addSystemConfig(system(physics).inStage(Stages.Update))
  .addSystemConfig(system(damageTick).after(physics))
  // 渲染
  .addSystemConfig(system(render).inStage(Stages.PostUpdate))
  // 调试组：默认关闭，并保证在渲染后绘制
  .addSystemConfig(system(drawFps).inStage(Stages.PostUpdate).inSet(DebugUiSet).after(render));

// 想要调试 UI 时，运行时打开：
// DebugUiSet.enabled(true);

app.run(120);
```

（`Time` / `createTimeSystem` 由 `DefaultPlugin` 或手动注册，见 docs/09。）

## 推荐：三段式开发心智模型

| 层 | 阶段 | 放的系统 |
| --- | --- | --- |
| 输入/准备 | `First`、`PreUpdate` | 时间推进、轮询输入、解析网络包 |
| 核心玩法 | `Update` | 移动、战斗、AI、物理 |
| 输出/收尾 | `PostUpdate`、`Last` | 渲染、UI、粒子发射、销毁清理 |

在这个骨架里：

- 用 Stage 保证"输入 → 逻辑 → 输出"的大方向；
- 用 before/after 保证核心玩法内部的小顺序；
- 用 SystemSet + runIf/enabled 做横切开关（调试、暂停、慢动作）。

## 小结

- 调度 = Stage 顺序（粗）+ 同阶段内 before/after 拓扑排序（细）+ SystemSet 批量管理；
- Stage 每结束会应用一次 Commands；tick 末尾清变更追踪与事件；
- `system(fn)` 构建器 + `addSystemConfig` 是最灵活组合方式，`.runIf/.enabled` 做运行时开关；
- 循环依赖会抛 `CircularDependencyError`；
- 自定义 Stage 可用 `addStageBefore/After` 精确定位。
